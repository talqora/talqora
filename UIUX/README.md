# UIUX —— 微信桌面端还原工作台

本目录是「把 web 端做成真正的微信」这项工作的事实来源:**怎么采的、采到什么、差在哪、为什么这么改、踩了什么坑**。

- 采样对象:微信 macOS 客户端 **4.1.15**,窗口 1000×720,@2x 截图
- 采样时间:2026-11-15
- 对应代码:`web/src`(React + antd)

## 结论速览(最该先看到的 5 条)

1. **三层分区靠明度,不靠描边**:竖栏 60 → 列表 240 → 聊天区余量,区域之间**没有 1px 分隔线**,我们现在多画了边。
2. **深色模式不是浅色取反**:浅色下越靠右越亮(`#e3e3e5 → #e6e6e8 → #fafafa`);深色下**列表最亮**(`#3b3b3d`)、聊天区最暗(`#1e1e1f`)。我们原来的深色把关系做反了。
3. **输入框是「一个描边盒子」**:工具栏在盒子**内部底部**,发送按钮在**右下**;我们是「顶部图标条 + 无边 textarea + 底部发送区」,且桌面端根本没渲染发送按钮——这是结构性差异,比色差更致命。
4. **尺寸是硬指标**:行高 64、列表头像 36、消息头像 40、气泡圆角 4、头部 52、搜索框 26。差 4px 就会被一眼看出「不是微信」。
5. **深色不能靠推导**:曾以为「浅色调暗即可」,实采后发现明度关系相反。任何色值都必须两套实采。

## 归档约定

新增一次采样,四件事一起做,否则下次没人能复现:

1. 全图 + 局部特写放 `assets/screens/`,命名 `{主题}-{区域}.png`
2. 数值写进 `02`,标注「实测」或「推定」
3. 差距与改造项写进 `03`,带状态
4. 新的坑写进 `01 §5`;新的决策权衡写进 `04 §4`
