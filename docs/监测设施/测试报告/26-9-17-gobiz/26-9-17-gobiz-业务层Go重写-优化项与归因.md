## 3. 归因

1. **"行锁是错误率唯一来源"反向验证成立**:解绑后错误率直接归零、p99 脱离 2s 平台;
2. **O1 的瓶颈转移**:INCR 消除行锁后,「每消息 2 次 ON CONFLICT + 双 Redis RTT」成为新瓶颈(v1 tp_r25 2961ms 排队不失败),四级缓存后 PG 写入压力降 3 倍;
3. **O3 根因**:Go 逐成员同步串行 PUBLISH(100×RTT≈111ms)vs Node `publishDownlink` 异步 fire-and-forget——已核对 server 源码;
4. **内存双相性**:Node 内存由消息负载驱动(Prisma 缓冲)、Go 由连接数驱动(每连接 2 流 goroutine),故"Go 更省"仅在消息负载场景成立;
5. **tp_r25 156ms vs 预期 50~150ms 的边缘差**:波动 2~3 倍来自同机 colima 资源竞争,非代码问题。
